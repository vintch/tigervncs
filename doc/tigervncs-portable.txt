TigerVNCs portable preferences
=============================

The session menu (Ctrl+Alt+M with the default modifiers) contains the
"Scale desktop to window" checkbox. This fits the complete remote desktop
inside the client area, preserving aspect ratio. Empty margins are normal
when the two aspect ratios differ. Scaling includes the local cursor and
pointer coordinates, and takes precedence over remote desktop resizing.
Unchecking restores the original 1:1 display and scrollbars.

The same checkbox is available under Options / Display. Options / Compression
controls the preferred encoding, automatic selection, color depth, compression
level and JPEG quality. To use a manually selected encoding/quality, disable
Auto select. The server must support the requested encoding.

Preferences are read from tigervncs.json beside the actual executable, including
when launched from a shortcut or a different working directory. A file is
created on first launch. Clicking the menu checkbox or accepting Options saves
the preferences immediately. Command-line overrides take precedence for the
current process; they are saved if the user subsequently accepts Options or
changes the menu checkbox. No fallback directory is used if saving fails.

The file uses UTF-8 JSON, schemaVersion 1, with a viewer object and a connections
array for saved computers. Unknown objects and fields are retained when
preferences or connection entries are saved.
Writes use a temporary file in the same directory and atomic replacement; an
invalid or unsupported configuration is reported rather than overwritten.

Connection manager
------------------
The small ? button opens About. Computers toggles the lower connection tree
and quadruples the connection window height. Its expanded state is saved in
manager.expanded. Right-click an entry or empty list space for the context
menu. New computer and New folder open an inline editor; Edit
changes the selected entry, including its parent folder. Nested folders are
supported. A nonempty folder must be emptied before deleting it. Selecting a
computer fills the server field; double-clicking uses the Connect action.
Manually replacing the address does not reuse another computer's credentials.

Move up and Move down reorder an entry among siblings, including mixed folders
and computers, without changing its parent. The unavailable boundary action is
disabled. Sibling ID arrays are stored in manager.order, keyed by parent ID;
older configurations keep their existing folders-first ordering until edited.
The optional expanded boolean on each folder persists its open/closed state.

Visible computers (all ancestor folders open, including top-level computers)
are monitored while the connection list is expanded. One ICMP echo is sent per
attempt. For N computers, the inter-packet interval is max(1 second, 3/N seconds)
and each computer is checked no more often than every three seconds. Thus more
than three computers have a longer polling cycle. All packets in this process
share an additional rate limiter. A reply turns the icon green; two consecutive
failures/timeouts turn it blue. One success resets the failure streak. Blue
means no recent ICMP confirmation, not necessarily a VNC service failure.

ICMP waits at most three seconds. DNS and ICMP execute away from the UI, with
a bounded worker pool (four by default, at most 64 with longer timeouts). Closing a folder/list cancels unsent work;
late results cannot update hidden, deleted or edited entries. No worker owns a
window or tree pointer, and closing the dialog never joins network workers.
Native operation buffers remain alive until Windows finishes the request.
Reachability is transient and is never written to settings. No credentials
are read or sent by monitoring, and no ping subprocess or raw socket is used.

Folders are stored as {id,name,parentId}; computers use
{id,name,address,username,folderId,password}. An empty parent/folder ID means
the top level. IDs are stable random identifiers. Missing parents, duplicate
IDs, cycles and hierarchies over 128 levels are rejected before writing.

Save password stores AES-256-GCM ciphertext, with a fresh 96-bit random nonce
and a 128-bit authentication tag. The computer entry ID authenticates the
ciphertext so passwords cannot be swapped between entries. The random 256-bit
key is wrapped by Windows DPAPI for the current user, and only its wrapped
form is stored in credentialKey. Windows owns the account protection; the
Windows account password is never read or stored by TigerVNCs. Moving the
JSON alone to another Windows account/computer will not unlock passwords.

When editing, a blank password preserves an existing saved password. Enter
a replacement to change it, or uncheck Save password to remove it. Passwords
are not decrypted merely to edit a name or folder. Failed key unlocks are
reported; the program never silently regenerates a missing or damaged key.
All general preferences, network and VPN paths, history, last server, saved
computers, passwords, folder state and certificate exceptions stay in this
JSON. On first launch after this upgrade, legacy registry preferences/history
are read once; existing JSON values take priority. settingsMigrated records
completion. No registry values are written or removed. Save as is no longer
shown; Load can still import an old .tigervnc file. No log file or state
folders are created outside the executable directory.

Connection recovery
-------------------
Options / Network configures connection establishment timeout (default 4s),
active session response timeout (default 4s), ICMP reply timeout (default 3s),
ping period per computer (default 3s), minimum packet interval (default 1s),
and Enable ping. These are stored under viewer in tigervncs.json.

The establishment deadline includes DNS, TCP and the RFB handshake; entering
credentials or approving certificates pauses it. An initial failure offers
Retry and Cancel. Cancel or closing the desktop returns to the initial window.

Established sessions recover silently after a network error or response stall.
The same desktop window and last complete image remain until fresh pixels
arrive. Credentials and the one-attempt session mode are retained in memory;
recovery does not prompt again. A quiet screen is valid: a tiny nonincremental
RFB request checks it before declaring a stall. Continuous byte progress keeps
slow frames alive even when their full transfer exceeds the response timeout.
No ICMP requests are sent while a session or its recovery is active. Pending
mouse buttons and timers are cleared before replacing the connection.
Only closing/cancelling the initial window ends the application.

Only the client-side image is scaled. This does not reduce the remote desktop's
resolution or by itself reduce network traffic.

macOS Screen Sharing compatibility
---------------------------------
The Apple RFB 3.889 banner is retained before normalizing the protocol version.
Apple compatibility sessions use ZRLE, Hextile or Raw. Unsupported preferred
codecs fall back to ZRLE; the options window shows the actual received codec.
JPEG quality does not affect lossless ZRLE/Hextile/Raw images. Compression level
is a server hint, not a lossy image-quality control.

Apple disconnects clients which request 8-bit pixel formats. Full color remains
available, and reduced color uses 16-bit RGB565 on the wire. The new 16-bit
choice is also available for other VNC servers. Existing saved 8-bit settings
automatically use 16-bit for Apple only. Other servers keep their 8-bit modes.

macOS session selection
-----------------------
The computer editor offers Current screen (default) and User session. The JSON
sessionMode field stores current-screen or user-session. Missing/null fields
default to Current screen. User session requires a saved username and password;
it uses Apple account authentication and requests that account's desktop.
macOS may reuse an existing desktop for the account, including its console
desktop if that same account is already active there.

Connect and double-click use the saved mode. A computer's context menu also
offers Connect to / User session and Connect to / Current screen.
These are one-attempt overrides; they do not edit the saved preference. Retry
keeps the selected mode, and returning to the main window clears the override.

Apple session selection is negotiated before framebuffer setup. Unsupported
or denied User session requests report an error rather than silently sharing
the console. Ordinary non-Apple Current screen connections retain standard RFB.
No new macOS accounts are created, no logout is requested, and the stored
credential key and ciphertext are preserved when only the mode is edited.

VPN profile associations (mod 1.0)
---------------------------------
Options / VPN configures OpenVPNConnectExecutable (default C:\Program Files\
OpenVPN Connect\OpenVPNConnect.exe) and WireGuardConfigurationDirectory
(default C:\Program Files\WireGuard\Data\Configurations).
At startup and after changing these paths, a background worker enumerates
Wireguard .conf/.conf.dpapi filenames and runs the exact configured OpenVPN
Connect executable with --list-profiles. The CLI has a four-second deadline,
a bounded output buffer, and no shell. Profile credentials are not imported.
CLI reference: https://openvpn.net/connect-docs/command-line-functionality-windows/

The computer editor has Associate VPN-Connection, provider and profile choices.
Each connection stores vpn: {enabled, provider, profileId}. OpenVPN uses the
stable profile ID; Wireguard uses the name without .conf/.conf.dpapi. Unavailable
saved profiles remain selectable and are marked unavailable. Missing clients,
access-denied folders and CLI failures leave the UI usable and are explained
in the profile tooltip. Profile discovery never activates or disconnects a VPN.
The standalone output artifact is dist/TigerVNCs.exe.

SSH power tools
---------------
Options / Tools stores PlinkExecutable (default C:\Program Files\PuTTY\plink.exe)
in the viewer section of tigervncs.json. A computer's Tools submenu offers
Power Off, Reboot, Force Power Off and Force Reboot. The submenu and all four
actions are disabled if plink is missing/not executable, either the username
or encrypted saved password is absent, or another power action is pending.
Ping status is purely informational and is never consulted for these actions.

Every action asks for confirmation, with an additional unsaved-data notice for
Force. Only the selected saved computer's own credentials are decrypted, from
an immutable snapshot taken before confirmation. SSH uses port 22 on the host
part of the VNC address; its VNC port/display number is not an SSH port.

The Mac must allow Remote Login, and the saved account must be permitted to run
sudo. Plink >= 0.78 is required for -pwfile. The host key must be trusted in
PuTTY, or pinned explicitly in the computer's optional sshHostKey JSON field.
Batch mode rejects unknown/mismatched keys without prompts or accepting them.
There is no bypass of SSH host-key verification.

All process work is isolated on a background thread with a 15-second deadline,
a hidden console-free child, restricted inherited handles and a kill-on-close
job. SSH passwords are provided through an ephemeral, local-only named pipe
restricted to the Windows account; the connecting process ID is checked.
The sudo password is provided on stdin. No password is put in process arguments
or temporary files. Stderr is discarded; there are no terminal/error windows.

Normal macOS commands are /sbin/shutdown -h now and /sbin/shutdown -r now.
Force uses /sbin/halt -q and /sbin/reboot -q, preserving filesystem sync but
bypassing graceful process termination. Fixed commands cannot contain computer
names, user-provided scripts or credentials. A root shell dispatches the action
with a one-second delay so the SSH acknowledgement can arrive before power is
lost. The final message means the command was accepted for dispatch, not that
the hardware has completed the shutdown/reboot. Missing SSH/sudo access,
authentication failures and timeouts all produce the same concise failure
message. The manager stays usable and remains open afterward.

Primary references:
https://raw.githubusercontent.com/apple-oss-distributions/system_cmds/main/reboot/reboot.8
https://www.puttyssh.org/0.84/htmldoc/Chapter3.html

Verification includes a non-networking plink stub and tests/integration/power_ssh.py,
which runs the real installed plink against a loopback-only synthetic SSH server.
That server validates authentication, stdin and command syntax, but NEVER runs
shutdown/reboot commands. It needs Paramiko in .tools/ssh-test-python and an
available loopback port 22. No live computer is powered off or restarted by tests.
